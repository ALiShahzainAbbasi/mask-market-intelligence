# ADR 0001 — Phase 1 local development baseline

Status: adopted for implementation under the user's instruction to begin Phase 1.
Date: 2026-09-02.

Superseded in part on 2026-09-03: [ADR 0002](0002-container-free-development.md) removes the Docker/container packaging and CI prerequisites, and [ADR 0003](0003-windows-first-lean-runtime.md) replaces Redis/Celery/Linux and external OIDC requirements for the private Windows MVP. This record is historical; use DEVELOPMENT.md for current commands. Other domain decisions not superseded remain in force.

## Decisions

- Node 24.19.0, pnpm 11.19.0; pnpm workspaces without a second task runner.
- CPython 3.12.13, uv 0.12.9; one universal uv lockfile and installable mask-api package.
- Next.js 16.3.4 / React 19.2.8, TypeScript 6.0.3 (deliberately retain this known peer-compatible line rather than adopting TypeScript 7 during scaffolding).
- Tailwind 4 and shadcn-compatible source-owned primitives. The only page is a local infrastructure status view, not a market dashboard.
- FastAPI, SQLAlchemy, Alembic, psycopg 3; exact direct pins are in apps/api/pyproject.toml.
- Celery 5.6.3 + Redis. Actual workers run in Linux containers; Windows is supported for editing and unit tests, not production worker execution.
- PostgreSQL 17 + pgvector extension; a separate non-superuser mask_app role is used by API/workers. Migration role enables extensions and grants access.
- Authentication approach for Phase 2: standards-based OIDC at the backend boundary plus secure HttpOnly server sessions. No provider account or auth workflow is provisioned now. Local smoke endpoints are disabled outside development and require a secret header.
- Storage approach for Phase 3: private S3-compatible object storage behind a backend adapter, with a constrained local filesystem adapter for development. No provider purchase or private upload processing in Phase 1.
- pytest/ruff/mypy for Python; Vitest/Testing Library/ESLint/TypeScript for web; OpenAPI-generated TypeScript contracts.
- Prettier 3.9.6 provides the non-mutating web-format check; its exact version was verified through npm. JUnit reports contain synthetic test results only and are ignored locally.
- ESLint stays at 9.39.4 because the installed React plugin fails with ESLint 10's removed context API. This compatibility pin is explicit; upgrade together when plugin support lands. redis-py is pinned to 6.4.0 because Celery/Kombu currently requires <6.5.
- pnpm commands are the cross-platform interface; Makefile aliases support Unix users.
- Docker image versions/digests are fixed in Dockerfiles and Compose. Compose v2.40.3 configuration validation passed locally; the supported Docker Engine/Desktop version must be recorded when the Windows Linux-container prerequisite is supplied.
- Phase 1 uses next build/next start for local production-mode checks; standalone deployment packaging is deferred to the approved Phase 21 target.
- No Sites/cloud deployment, alternative database, market tables, scrapers, model calls, or scoring in Phase 1.

## Verification and constraints

Package versions were checked against their official npm/PyPI registries. Dependency lockfiles are generated by package managers, not fabricated. The local Codex bundle provides the pinned Node/Python versions. Docker CLI/Desktop are absent on this machine, so Docker-backed migrations, Postgres/vector tests, Redis/Celery integration, clean Compose startup, and hosted CI remain unverified until that prerequisite is supplied.

This does not approve numerical scoring/normalization/confidence proposals D02-D06.
